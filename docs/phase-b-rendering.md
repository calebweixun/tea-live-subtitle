# Phase B｜逐行渲染

Phase A（`phase-a-layout.md`）把所有字幕塞進**一個**私有 `text_ft2_source`。那樣做不到的事情，
使用者在真實 OBS 裡都看到了：

| 現象 | 根因（`text_ft2_source` 的行為，OBS 31.1.1 `plugins/text-freetype2`） |
|---|---|
| 對齊無效，永遠從左邊長 | `text_ft2` 本身沒有對齊；Fixed 模式下 `custom_width >= 100` 時它回報的寬度**就是** `custom_width`（`text-functionality.c` `set_up_vertex_buffer`），外層算出的剩餘空間永遠是 0 |
| 一直往旁邊長 | 舊來源被遷移成 Auto；Auto 且 `custom_width < 100` 時 `text_ft2` 完全不折行 |
| 「文字顏色／描邊顏色」看起來是漸層 | `color1`／`color2` 是字形由上到下的漸層（`set_rect_colors2`）；描邊與陰影用 `use_color=false` 畫，固定黑色 |
| 沒有文字底色、沒有淡出 | 單一文字塊做不到逐行的方塊與透明度 |

## 做法

```
caption-state（執行緒安全）──snapshot──▶ captions-source.c（圖形執行緒）
   每行：key、已提交文字、未確定尾巴        │
                                          ├─ caption-display.h（純函式）：折行、對齊、行數上限、換句、淡入淡出
                                          ├─ 3 個私有 text_ft2「worker」：量字寬、把文字畫進貼圖
                                          └─ 貼圖快取：每個「片段」畫一次，之後只帶透明度重畫
```

* **不是每行一個子來源。** 每個 `text_ft2` 實例都帶一張 2048×2048 的字形圖集（CPU＋GPU 約 8 MB），
  一行一個會吃掉數十 MB，而且新行出現時要先建立子來源（載入字型）。改成固定 3 個 worker：
  記憶體固定約 24 MB，不隨行數增加；worker 的圖集快滿時（依字級估算）會在閒置時換一個新的。
* **量字寬。** `text_ft2` 的寬度＝各字 advance 相加（沒有 kerning）＋固定的描邊邊距，所以每個字只要量一次
  （worker 顯示單一字、讀 `obs_source_get_width`），之後折行與對齊都是同步的算術。邊距用「國」與「國國」
  的寬度差算出來，不寫死 `text_ft2` 的常數。所有 worker 先快取同一串字（`TEA_PRIME_TEXT`），讓基線高度一致。
* **片段貼圖。** 一行由數個片段組成：每次新接上的文字是一段、未確定尾巴另外一段。每段由 worker 畫進自己的
  `gs_texrender` 一次；已提交的字不會變，所以這張貼圖之後只會被重畫、不會重算。淡入以片段為單位：
  **只有新接上的那一段淡入，已顯示的字保持不動**。淡出以行為單位。
* **不閃爍。** 新版面只有在它需要的貼圖全部就緒後才換上；在那之前畫面維持上一版（多等 1–3 個 frame）。
* **效能。** 沒有字幕變化時每個 tick 只做淡入淡出的 alpha 計算；版面只在內容、設定或淡出結束時重算。
  字幕每秒更新數次時，每次只需要量新出現的字、畫新的片段。

## 折行與「只增不改」

* 中文、日文、韓文、emoji 字與字之間可以斷；拉丁字母只在空白處斷；`，。」）` 等不放行首（超出時懸掛在行尾），
  `「（` 等不放行尾；組合字元、ZWJ 序列不拆開。
* **已顯示的字不會被擠到下一行。** 一行超出寬度時，斷點只能落在「這次新接上的那一段」之內（或它的開頭）。
  所以英文字若剛好跨在兩次更新之間，可能在行尾被拆成兩半——這是刻意的取捨，換來的是畫面上的字永遠不動。
* 行數上限與淡出移除的都是**整行**；剩下的行內容不變。

## 換句（server 的切段靜音）

* 每個 server segment 就是一行；segment 在語音偵測（Silero VAD）聽到夠長的靜音時結束。「換句偵測時間」
  現在就是這段靜音長度，以 `session.start.segmentation = {"end_silence_ms": N}` 送給 server
  （docs/04「切段控制」，300–3000 ms，只限 continuous）。server 在
  `session.started.preview_policy.endpoint_silence_ms` 回報實際生效的值，Tools 對話框與屬性視窗都會顯示。
* 只在 `/v1/capabilities` 有 `features.segmentation_control.end_silence_ms = {min,max,default}` 時才送，
  並夾在 server 宣告的範圍內；沒有這個能力的 server 不送（舊 server 會把未知欄位當 `protocol_error`），
  屬性視窗顯示「這台伺服器不支援」。宣告了卻拒絕（`protocol_error`／`unsupported_option`）時，下一次連線
  拿掉這個欄位、改用 server 預設，不當成致命錯誤。它是 `session.start` 的欄位，所以是連線類設定
  （「套用連線設定」或關閉視窗才生效），和穩定字幕一樣。
* **不在 client 做 VAD，也不再用「文字多久沒來」判斷換句。** server 已經對同一段音訊跑 VAD，而且知道哪些字
  來自哪段音訊；client 看到的文字到達間隔被 server 約 800 ms 的預覽節奏量化（850 ms 常常切、900 ms 幾乎不切，
  就是這個原因），第二個偵測器只會跟 server 的切法不一致，也無法把斷點放在正確的字上。
* 遷移：舊的 `line_break_pause_ms` 若有值，轉成新的 `sentence_break_silence_ms`（0＝server 預設，
  其他值夾到 300–3000），舊鍵移除。新來源預設 870 ms（使用者實際使用的值）。

## 標點換行

講話快的人很少停頓到換句偵測時間（server 的切段靜音，預設 870 ms），一個 server segment 會裝好幾個子句，
這一行就只能一直長到折行為止。「標點換行」讓同一個 segment 裡遇到標點就換到新的一行。

* 選項：關閉／句末（。？！…；，也就是 . ? ! ;）／句末＋逗號（再加上 ，、,）。全形與半形一視同仁。
  「逗號換行最短字數」（預設 8，0–40）：這一列可見字數少於 N 時逗號不換行；句末標點永遠換行。
* 標點留在它結束的那一列，下一列從下一個非空白字元開始；「。」」「？！」「……」這種連續標點與收尾括號留在同一列。
* 小數點與千分位（3.5、1,000）、後面直接接英數字的點（www.example.com、U.S.A）、縮寫（Mr.、Dr.、e.g.、
  i.e.、單一字母的人名縮寫 J.）都不換行（`tea_punct_break_end()`，有單元測試）。
* **畫面上的字不會移動。** 換不換行只由「到標點後第一個字為止的文字」和它所在的那一列決定：在標點後面的字
  出現之前就已經決定，文字只往後長的時候永遠不會改。所以標點後面的字從出現的第一刻就在新的一列，
  不會先接在同一列、之後再跳下去。
* **已確定與未確定的標點都算。** 尾巴句末的「。」本來就不顯示（每次預覽都以句號結尾）；尾巴中間看得到的標點會換行。
  依據：在重播裡，大多數換行發生時那個標點還在尾巴裡（見下表「在尾巴」），因為 stable 提交比預覽慢；
  「只在已確定標點換行」的話，逗號提交的時候後面的字早就接在同一列了，要嘛永遠不換、要嘛把已顯示的字擠下去。
  尾巴的標點如果被之後的預覽改掉，那屬於尾巴修正（改寫的是未確定的字），不是版面移動。
* 行數：換出來的列是同一個 segment 的不同**列**：算在「畫面最多行數」（2）裡，不算在「最多保留句數」（3，
  以 server segment 計）裡。同一句較早的子句列會在行數上限下整列捲出畫面（預期行為）。
* 淡出以 segment 為單位：同一句的所有子句列一起淡出；segment 還開著、還有人在說話時不淡出（見下一節）。
* 預設：新來源「句末＋逗號」、最短 8 字（`render_schema_version=3`）；既有來源關閉，外觀不變。

裝好幾個子句，才看得出效果。換行都在標點第一次出現的同一個 frame 生效（標點與後面的字一起到）。

## 淡出：只看「還有沒有在說話」

* 真實模型的穩定提交間隔（同一段內，900 ms 設定）：中位數 881 ms、p95 3.8 s、最長 7.1 s（1200 ms 設定最長 9.5 s）。
  若淡出計時只在已確定文字變動時重設，1500 ms 的淡出一定會在說話途中觸發，整行消失、之後才一次冒出來。
* 29 分鐘的真實直播 soak（講道、三位講者，end_silence 300／600）另外顯示：segment 還開著時，文字可以停住超過
  1.5 秒——server 不重送相同的預覽、講者停頓或唱詩、VAD 在背景音樂下一直判定為語音。舊規則（「整個 session
  1.5 秒沒有 transcript 活動就淡出開著的行」）在兩條 trace 裡讓開著的行在說話途中淡出 1／5 次，之後文字繼續或 final
  才到。
* 規則（`tea_display_line_fade_ref()`）：
  - **server 還沒結束這個 segment（沒有 transcript.final、收尾的 stable、skipped／error／cancelled）而且連線還在時，
    這一行不淡出。**
  - 安全網：開著的行只有在 `TEA_OPEN_LINE_TIMEOUT_MS`（10 秒，不是使用者設定）內**什麼都沒收到**——該段沒有事件、
    整個 session 沒有 transcript 事件、`audio.ack` 的 `received_sample` 也沒有前進——才開始淡出。server 一直收音訊
    （每 100 ms 左右一則 ack）時，開著的行就一直留著；server 卡住或忘了結束 segment 時，10 秒後照常淡出。
  - 已結束的行從結束那一刻起算使用者的淡出延遲（預設 1500 ms）；之後的 session 活動或 ack 不再延長它。
  - 斷線照舊：`hold_for_reconnect()` 把所有行凍結成已結束，之後依淡出設定淡出，長時間斷線仍會清掉。
  - ack 進度不算字幕修訂（不觸發重新排版），來源每個 tick 讀一次 `tea_caption_state_server_progress()`。
* 畫面上的版面可能比字幕狀態晚幾個 frame（等量字、畫貼圖），淡出的 alpha 在繪製時用該行最新的活動時間計算。

## 未確定尾巴：畫面上的字不倒退

「顯示未確定文字」只在穩定字幕模式有作用，未確定的部分以「未確定文字不透明度」（預設 50%）畫在已確定文字後面。

### 對齊：忽略標點與空白

模型的 partial 常把已確定的字重說一遍、只是逗號或空白不同（「好，我們今天」對「好我們今天，」）。逐 byte 比對會
認不出來，整句被當成新的一句接在後面，畫面上就同一句出現兩次。所以尾巴的對齊（`src/caption-align.h`）先把兩邊
**正規化**：去掉中英文標點與空白、英文轉小寫、全形英數轉半形、幾個常見異體字（爲→為等）合併；在正規化後的
字串上對齊，再對回原文的 byte 位置，尾巴仍用 partial 原本的字（含標點）。對齊依序嘗試：

1. partial 以已確定文字開頭（正規化後）：取其後；
2. partial 的開頭與已確定文字只差少數字（約每 4 字 1 處、2–3 字的已確定文字容許 1 處）：跳過對應的長度；
   開頭 3 字相同、差異不超過一半的「重說」也算；
3. partial 的開頭與已確定文字的結尾重疊至少 3 字：取重疊之後——預覽視窗往前移了；
4. 兩邊共同的連續字不超過 4 個、partial 的開頭也不像已確定文字的任何一段：partial 是新的一句（真實模型常只
   預覽長段落的最後一個片語），整句接在後面；
5. 其他情況（有一大段相同、但對不上位置）：這個 partial 不用，畫面維持。

4 之前還有三條「重說」規則，都是從 soak trace 找到的外掛端重複（partial 被當成新的一句接在後面）：

* partial 的開頭正好是已確定文字的結尾（至少 2 字，例如已確定「…我們」、partial「我們一起…」）：預覽視窗往前移了，
  取重疊之後；
* partial 裡有一段（至少 3 字）與已確定文字的最後幾個字相同，只是最後至多 3 個字聽成別的，而且它在 partial 裡的位置
  不比在已確定文字裡晚超過 2 字：這是把已確定文字的結尾重說一遍，從那段之後（再跳過已確定文字剩下的字數）接；
* partial 的開頭像已確定文字的**開頭**，或兩邊共同的一段（至少 3 字）在兩邊的位置差不到 2 字：整句重說但聽得
  不一樣，不算新的一句（無法對齊就不用這個 partial）。

**去重防護**：任何會讓同一行出現「同一段正規化後 4 字以上的字重複兩次」的尾巴都不採用，除非 server 自己的
partial 就重複了它（`tea_norm_has_new_repeat()`）。

### 尾巴的更新

* 假設句尾的標點（「。」「？」等）不顯示：模型每次預覽都以句號結尾，接下來的預覽又把它換成新字，畫面上看起來就是
  「字被收回」。句號等 final 或提交時才出現。
* 新的尾巴與畫面上的尾巴開頭一致的部分（正規化後、約每 10 字容許 1 處差異，短的開頭必須完全相同）保留畫面上的字，
  其後接上新尾巴的後段。這避免「開頭一個字改了」就整條尾巴重畫。合併結果比畫面上的短就不採用。
* 其他情況：新的尾巴比畫面上的短就忽略（不收回）；否則取代（未確定的字可以被**修正**，不會被**移除**）。
  已確定文字追上時，已確認的部分從尾巴移進已確定文字（正規化後對齊），畫面不變；已確定文字與尾巴衝突時以
  已確定文字為準（已確定文字本身從不改）。
* 尾巴參與折行與對齊，但不會把已確定的字擠走（尾巴造成的超寬一律從尾巴開始換行）。文字底色涵蓋尾巴。

## 一句結束時：已確定的字不收回，尾巴換成 final

規則（`caption-state.c` 的 `tea_close_with_final_locked()`，結果可由 `tea_caption_state_last_close()` 取得）：

* **已確定文字從不移除或改寫。**
* final 延伸畫面上的字（已確定＋尾巴，正規化後比對）：顯示它，尾巴併入已確定文字（「延伸」）。
* 否則，尾巴換成 final 在已確定文字之後的部分（正規化後對齊，找不到對應位置時取 final 與已確定文字最長共同段之後
  的部分）（「採用 final」）。尾巴本來就是猜測，final 是 server 的定稿；舊規則「畫面維持原樣」在 2026-09-28 的
  300 ms trace 裡讓 20 段停在錯字或重複的尾巴上（例：第 4 段停在同一句說兩次的尾巴；第 15 段停在
  「…不是讓你不不需要別人」，final 是「…不是讓你不需要別人。」）。
* 保留尾巴只有兩種情況（「保留尾巴」）：
  1. 採用 final 的結果只是畫面上的字少了結尾：它什麼都沒修正，只會收回字（例：音訊結束，final 在已確定文字
     之後沒有新字）；
  2. **片語遺漏**：final 比畫面上短、完全包含在畫面上的字裡，而且尾巴仍是最新 partial 的內容。

  真實模型在一個 segment 含兩個片語時，final 常丟掉其中一個（例：畫面「你不會寫程式的話」，final「你不會寫程式的」；
  畫面「遲遲未定的原整理裡面的聲音與字幕」，final「整理裡面的聲音與字幕。」）；這時換成 final 只會收回觀眾
  已讀過、而且是對的字（1200 ms trace 的「醉人的芬芳步伐踉蹌，險些跌倒在地。都行，沒差」對 final「醉人的芬芳。」
  會一次收回 17 個字）。
* 這一行仍然算結束（淡出從此刻起算）；之後收尾的 stable 不再改變它；segment.skipped／cancelled／斷線凍結畫面上的內容；
* 逐字稿、匯出與存檔只認 `transcript.final`，這裡只是顯示。
* 尾巴關閉時，畫面上只有已確定文字，final 的後段照樣接上。

### 一次冒出很多字

重播 trace 時，最大的一次變化來自模型自己改寫整段預覽（例：「okay拜拜收工」變成「okay bye bye so bye bye so」），
不是折行或行數上限：行數上限只捲掉最上面的列，不移動任何一列的字（版面移動仍為 0），而重播工具的「一次冒出
多少字」只計實際新增的字（最長共同子序列以外），捲動不算。

## 診斷列

「在畫面上顯示診斷列」開啟時，字幕下方多一行小字（字級的一半），顯示連線狀態、語音狀態、輸入音量與距離上次出字的
秒數（見 [`diagnostics.md`](diagnostics.md)）。它和字幕分開：不淡出、不在文字底色裡、不算在行數上限裡；
來源高度會多出這一行。文字每 250 ms 更新一次，只在內容改變時重畫。

## 離線重播工具

`tests/replay/caption-replay.cpp` 把真實 server 事件 trace（JSONL：`{"t_ms", "event"}`）餵進外掛真正的
`caption-state.c` 與 `caption-display.h`，照 `captions-source.c` 的流程模擬畫面，印出每次畫面變化，並標出
「段落還開著時畫面上的字變少或消失」的每一刻（淡出、行數上限、尾巴收回、尾巴修正）、每一句結束時畫面與
server 文字的關係，以及一個 frame 內最多冒出多少字。建置方式見 `tests/replay/README.md`。

## 設定套用

* OBS 的來源「屬性」視窗在每次修改約 500 ms 後呼叫 `update()`（`shared/properties-view` 的 update timer），
  外觀設定因此本來就即時套用；外掛這邊確保它們**只重畫、不重連**。
* 會送到 server 的設定（位址、連接埠、Token、穩定字幕——`stable` 是 `session.start` 欄位，session 中途不能切換）
  在屬性視窗開著時先暫存，按「套用連線設定」或關閉視窗時才重連；沒有屬性視窗時（復原、腳本、obs-websocket）
  立即套用。取消會還原成原本的值，不會重連。音訊來源切換不重連，只換擷取來源。
* Tools 選單的「TEA ASR 字幕設定」對話框只有連線狀態與「全部重新連線」，沒有外觀設定。

## 舊來源與新來源

新功能的預設值都是「看起來跟以前一樣」：淡入、淡出、換句（server 預設）、畫面行數上限、底色、尾巴全部關閉；
既有來源保留自己的值。新建的來源（沿用 Phase A 的新來源偵測，`render_schema_version=2` 標記）寫入使用者在真實
直播中定下來的設定：漸層上色 #FFFFFF、下色 #DBE577、黑色描邊與陰影、文字底色（內距 0）、固定寬度 1800 px、
置中、內距 10、最多 3 句、畫面最多 2 行、換句 870 ms、等待提示、淡入、淡出（1500 ms 後、200 ms）、顯示未確定文字，
以及標點換行「句末＋逗號」、最短 8 字（`render_schema_version=3`）。
唯一刻意改變舊來源外觀的是對齊——它以前確實是壞的。

Auto 模式沿用舊語意：`custom_width >= 100` 時在那個寬度折行、外框寬度不變；否則不折行、外框跟著最寬的一行長。
外掛不會偷偷改成折行，而是在屬性視窗顯示提示，建議改成「固定寬度」。
