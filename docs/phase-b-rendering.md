# Phase B｜逐行渲染

Phase A（`phase-a-layout.md`）把所有字幕塞進**一個**私有 `text_ft2_source`。那樣做不到的事情，
使用者在真實 OBS 裡都看到了：

| 現象 | 根因（`text_ft2_source` 的行為，OBS 31.1.1 `plugins/text-freetype2`） |
|---|---|
| 對齊無效，永遠從左邊長 | `text_ft2` 本身沒有對齊；Fixed 模式下 `custom_width >= 100` 時它回報的寬度**就是** `custom_width`（`text-functionality.c` `set_up_vertex_buffer`），外層算出的剩餘空間永遠是 0 |
| 一直往旁邊長 | 舊來源被遷移成 Auto；Auto 且 `custom_width < 100` 時 `text_ft2` 完全不折行 |
| 「文字顏色／描邊顏色」看起來是漸層 | `color1`／`color2` 是字形由上到下的漸層（`set_rect_colors2`）；描邊與陰影用 `use_color=false` 畫，固定黑色 |
| 沒有文字底色、沒有淡出 | 單一文字塊做不到逐行的方塊與透明度 |

## 做法

```
caption-state（執行緒安全）──snapshot──▶ captions-source.c（圖形執行緒）
   每行：key、已提交文字、未確定尾巴        │
                                          ├─ caption-display.h（純函式）：折行、對齊、行數上限、換句、淡入淡出
                                          ├─ 3 個私有 text_ft2「worker」：量字寬、把文字畫進貼圖
                                          └─ 貼圖快取：每個「片段」畫一次，之後只帶透明度重畫
```

* **不是每行一個子來源。** 每個 `text_ft2` 實例都帶一張 2048×2048 的字形圖集（CPU＋GPU 約 8 MB），
  一行一個會吃掉數十 MB，而且新行出現時要先建立子來源（載入字型）。改成固定 3 個 worker：
  記憶體固定約 24 MB，不隨行數增加；worker 的圖集快滿時（依字級估算）會在閒置時換一個新的。
* **量字寬。** `text_ft2` 的寬度＝各字 advance 相加（沒有 kerning）＋固定的描邊邊距，所以每個字只要量一次
  （worker 顯示單一字、讀 `obs_source_get_width`），之後折行與對齊都是同步的算術。邊距用「國」與「國國」
  的寬度差算出來，不寫死 `text_ft2` 的常數。所有 worker 先快取同一串字（`TEA_PRIME_TEXT`），讓基線高度一致。
* **片段貼圖。** 一行由數個片段組成：每次新接上的文字是一段、未確定尾巴另外一段。每段由 worker 畫進自己的
  `gs_texrender` 一次；已提交的字不會變，所以這張貼圖之後只會被重畫、不會重算。淡入以片段為單位：
  **只有新接上的那一段淡入，已顯示的字保持不動**。淡出以行為單位。
* **不閃爍。** 新版面只有在它需要的貼圖全部就緒後才換上；在那之前畫面維持上一版（多等 1–3 個 frame）。
* **效能。** 沒有字幕變化時每個 tick 只做淡入淡出的 alpha 計算；版面只在內容、設定或淡出結束時重算。
  字幕每秒更新數次時，每次只需要量新出現的字、畫新的片段。

## 折行與「只增不改」

* 中文、日文、韓文、emoji 字與字之間可以斷；拉丁字母只在空白處斷；`，。」）` 等不放行首（超出時懸掛在行尾），
  `「（` 等不放行尾；組合字元、ZWJ 序列不拆開。
* **已顯示的字不會被擠到下一行。** 一行超出寬度時，斷點只能落在「這次新接上的那一段」之內（或它的開頭）。
  所以英文字若剛好跨在兩次更新之間，可能在行尾被拆成兩半——這是刻意的取捨，換來的是畫面上的字永遠不動。
* 行數上限與淡出移除的都是**整行**；剩下的行內容不變。

## 換句偵測

* server 在約 0.9 秒靜音時切出新的 segment（`endpoint_silence_ms=900`），每個 segment 本來就是新的一行。
  這個值**無法由 client 在 `session.start` 設定**（`SessionStart` 是 `extra="forbid"`，沒有這個欄位，
  送了會被當 `protocol_error`）。要讓使用者調整 server 的斷句靜音長度，需要 server 新增欄位。
* client 端的「換句偵測時間」補上 server 不會切的情況：同一個 segment 的文字停了超過設定時間
  （例如背景噪音讓 VAD 沒偵測到靜音），接下來的字就從新的一行開始。新來源預設 3000 ms：
  穩定字幕每 800 ms 最多提交一次、兩版一致才鎖定，連續講話時兩次提交之間可能隔 1.6–2.4 秒，
  3 秒以上才算真正的停頓。舊來源預設 0（關閉）。

## 未確定尾巴

「顯示未確定文字」只在穩定字幕模式有作用：同一段最新的 `transcript.partial` 以已提交文字開頭時，多出來的部分
以「未確定文字不透明度」（預設 50%）畫在後面；不以其開頭就不顯示尾巴。尾巴參與折行與對齊，但不會把已提交的字
擠走（尾巴造成的超寬一律從尾巴開始換行）。文字底色涵蓋尾巴，讓底色不會在尾巴被確認的瞬間跳寬。

## 設定套用

* OBS 的來源「屬性」視窗在每次修改約 500 ms 後呼叫 `update()`（`shared/properties-view` 的 update timer），
  外觀設定因此本來就即時套用；外掛這邊確保它們**只重畫、不重連**。
* 會送到 server 的設定（位址、連接埠、Token、穩定字幕——`stable` 是 `session.start` 欄位，session 中途不能切換）
  在屬性視窗開著時先暫存，按「套用連線設定」或關閉視窗時才重連；沒有屬性視窗時（復原、腳本、obs-websocket）
  立即套用。取消會還原成原本的值，不會重連。音訊來源切換不重連，只換擷取來源。
* Tools 選單的「TEA ASR 字幕設定」對話框只有連線狀態與「全部重新連線」，沒有外觀設定。

## 舊來源

新功能的預設值都是「看起來跟以前一樣」：淡入、淡出、換句、畫面行數上限、底色、尾巴全部關閉。只有新建的來源
（沿用 Phase A 的新來源偵測，加上 `render_schema_version` 標記）寫入建議值：淡入、淡出（6 秒後、400 ms）、
換句 3000 ms、畫面最多 2 行。唯一刻意改變舊來源外觀的是對齊——它以前確實是壞的。

Auto 模式沿用舊語意：`custom_width >= 100` 時在那個寬度折行、外框寬度不變；否則不折行、外框跟著最寬的一行長。
外掛不會偷偷改成折行，而是在屬性視窗顯示提示，建議改成「固定寬度」。
